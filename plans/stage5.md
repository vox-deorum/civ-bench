# Stage 5 — report

**Goal.** Assemble the produced `AnalysisResult`s into a complete report — proving the full **extract → load → adjust → analyses → report** pipeline with **zero training**. **Status: built & validated.**

**Layout as built.** `bench/reports/` holds `errors.py` (`ReportError`), `model.py` (the renderer-agnostic document IR: `ReportDocument` → `FamilyGroup` → `Section` → `Figure`/`Table`, plus the `ControlledSeedDocument` for the controlled-seed chapter), `templates.py` (the document builder: `default_template` groups sections into the five analysis families, ratings / prediction / calibration / performance / exploratory, and gives the controlled-seed section its own chapter group, parallel to the families, when the resolved sections carry its analysis), `context.py` (the `ReportBuildContext`: run metadata, resolved sections, and a containment-checked loader for the *full* named CSV artifacts of each selected manifest, so the controlled-seed chapter rebuilds complete tables without the report stage ever reading canonical tables or estimator predictions), `controlled_seed.py` (the chapter document builder `controlled_seed_document` + the `chapter_seeds` listing behind the sidebar's per-seed sub-entries + the HTML renderer `render_controlled_seed_site`, standalone with a centered layout when no navigation is passed + the static vanilla-JS asset), `render.py` (`render_markdown` + `render_html` walk the *same* IR so the two formats stay faithful; `render_html_site` emits the family pages plus the controlled-seed chapter when the document carries it (the chapter group's page is `controlled-seed/index.html`, the seeds are its sidebar sub-entries, the section's overview card links to the chapter page, and `render_controlled_seed_site` is called with the `../`-prefixed sidebar); tables via `DataFrame.to_markdown`/`to_html`, a tiny inline-markdown subset converted for HTML; the shared stylesheet also carries the controlled-seed styles), and `runner.py` (`run_report` → resolve sections and formats, read each analysis's `result.json` manifest, copy artifacts into a self-contained `assets/<id>/` tree, build the document through `default_template`, then render md and html uniformly: html includes the chapter pages, and a run whose formats exclude html warns when the document carries the chapter). The CLI dispatches `node.kind == "report"` to `run_report` at the tail of `run`, and the standalone `civ-bench report` re-renders from existing artifacts without re-running any analysis. The package is import-light (pandas + stdlib only — figures are already PNGs on disk), so it pulls neither matplotlib nor R.

**The manifest.** The report re-renders from disk, so the **analysis runner now writes a `result.json` manifest** beside each analysis's artifacts (`<root>/analyses/<id>/result.json`: id, module, summary, metadata, ordered table/figure filenames, `empty` flag). This is the contract that lets `civ-bench report` reproduce the document from artifacts alone (invariant 3) — and it is written even for an empty result, so an empty section renders as *produced-but-empty* rather than being mistaken for a never-run stage.

## Files created

- `bench/reports/` — `errors.py`, `model.py`, `templates.py`, `render.py`, `runner.py`, `__init__.py`. The old notebook narratives (`performance/`, `exploratory/`, `predict/`) are now *generated* sections — each analysis's `AnalysisResult` is walked in DAG order and rendered; no analysis hardcodes its place (invariant 3).
- `bench/analyses/runner.py` — extended to persist the `result.json` manifest (see above).
- `bench/cli.py` — `report` added to `_IMPLEMENTED_KINDS`; `run` dispatches the report node; the standalone `report` command renders from existing artifacts.
- `tests/test_report.py` — section resolution, manifest→document→md/html render, asset copying, empty-section handling, byte-stable re-render, and the loud errors (missing manifest, unknown section id, unsupported format).

- `bench/analyses/performance/controlled_seed_report.py` — the `performance.controlled_seed_report` analysis (stage 4 module, stage-5 consumer): aggregates the controlled design by `(seed, player_id)` into `seed_player_summary`, `seed_player_probability` (fixed 101-point normalized-progress grid, per-run interpolation without extrapolation), and `seed_player_index`, with the dedicated Vanilla baseline canonicalized to `Vanilla | Vanilla` from the strength stage's `baseline_experiment`. Full design: [controlled-seed-report.md](controlled-seed-report.md); schema docs: `configs/benchmark.md` §6.2.
- `bench/reports/context.py`, `controlled_seed.py`, and the `ControlledSeedDocument` model: the report build context; the chapter document builder `controlled_seed_document` and the HTML renderer `render_controlled_seed_site` in `controlled_seed.py` (the chapter page `controlled-seed/index.html` with two heatmaps per seed, the Vanilla condition as a separate isolated row, and the source tables; one detail page per seed-player pair under `controlled-seed/` with strategist checkboxes, the Vanilla reference curve, and the comparison table; every chapter page framed by the site sidebar, one sub-entry per seed); and the static `assets/controlled-seed-report.js` (deterministic vanilla JS for tooltips, checkbox filtering, and the SVG chart with its per-progress comparison tooltip; no packages, no network).
- `configs/benchmark.full.template.json` wires the analysis with `"enabled": false`.
- `tests/test_controlled_seed_report.py` — analysis aggregation/baseline/curve/error tests plus report rendering, escaping, blank-cell, warning, and byte-stable re-render tests.

## Config wiring (`report`)

`out_dir` (authored under the base output root and re-rooted by `output.suffix` §2.1; the run writes `<root><suffix>/<name>/`), `formats` (`md`/`html` implemented; `pdf` is schema-reserved and errors loudly at render time; an omitted `formats` defaults to `["md", "html"]`), `sections` (null = every enabled analysis in canonical-family order, members in dependency order; or an ordered id list), `title` (null = derive from `name`), `include_disabled:false`. **Section ordering is grouped by family:** the report buckets sections into the five family chapters (families ordered by first appearance in the resolved list), and an explicit `sections` list is honored **within** each family block — it does *not* interleave a section between two other families' chapters (a list like `[pred_a, explore_x, pred_b]` renders `pred_a, pred_b` under Prediction, then `explore_x` under Exploratory). A repeated id is kept once (warned). When the resolved sections carry an enabled, non-empty `performance.controlled_seed_report` analysis (at most one enabled instance per run; more is a config-load error), its section leaves the performance family and becomes the controlled-seed chapter, parallel to the families: the chapter pages under `controlled-seed/` render automatically with the html format, a `formats` list without `html` warns and skips the pages, and the analysis's section omits its link to `controlled-seed/index.html`.

## Done

`civ-bench run --config configs/benchmark.dev.json` (a local load-only config copied from `benchmark.pretrained.template.json`) produces the report under the resolved output root — `reports-dev/civbench-dev/` (`report.md` + `report.html` + `assets/`) end-to-end from the copied pre-trained estimators — **no training invoked**. This is the milestone: the whole pipeline works on pre-trained estimators. Verified on real data (15 sections across the five families).

## Verification

- ✅ The report contains a section for every enabled core analysis, grouped into families (members in dependency order).
- ✅ `report` re-render (`civ-bench report --config …`) reproduces the document **byte-identically** from existing artifacts (deterministic: no timestamps).
- ✅ Section ordering: `sections:null` ⇒ canonical family order; an explicit `sections` list ⇒ authored order **within each family chapter** (families ordered by first appearance; cross-family interleaving is not preserved — sections are regrouped into their family block). Missing manifest / unknown section id / `pdf` format all fail loud; a duplicate section id renders once.
- ✅ Anchors are namespaced + de-duplicated (`family-*` / `section-*`), so a family title and a section id that slug to the same string no longer collide; the markdown emits explicit `<a id>` anchors that the TOC links target.
- ✅ Markdown tables escape `|` in cell values and render NaN as empty (matching the HTML `na_rep=""`), and `assets/` is rebuilt from scratch each render so a removed artifact leaves no orphan in the self-contained tree.
