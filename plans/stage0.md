# Stage 0 — scaffold & infrastructure

**Goal.** Stand up the installable package, the JSON config loader/validator, the DAG pipeline, and the shared infra (catalogs, data, stats, plotting) that every later stage imports. After this stage a config can be loaded, validated, and its DAG printed — without running any analysis. **Status: built & validated.**

## Files created / ported

- [`pyproject.toml`](../pyproject.toml) — `pip install -e .`, exposes the `civ-bench` CLI entrypoint (`bench.cli:main`); declares the full dependency set (see AGENTS.md §Dependencies) as plain requirements (no extras).
- [`bench/__init__.py`](../bench/__init__.py) (version only, kept import-light), [`bench/cli.py`](../bench/cli.py) — `civ-bench extract|run|report` + `--config`/`--only`/`--skip`/`--dry-run`.
- [`bench/config/`](../bench/config/) — load + validate the run-spec (`configs/benchmark*.json`) per [../configs/benchmark.md](../configs/benchmark.md) §8 (unknown keys / missing required = hard error); typed config objects ([`models.py`](../bench/config/models.py)); **resolves the output root** (default `reports`, configurable `suffix` → `reports-cross`) and threads it through `OutputConfig.resolve()`. Schema constants live in [`schema.py`](../bench/config/schema.py); the validator in [`loader.py`](../bench/config/loader.py).
- [`bench/pipeline/`](../bench/pipeline/) — build the stage DAG from kind-ordering + `needs` + `uses`, topo-sort (Kahn, deterministic), and render it ([`dag.py`](../bench/pipeline/dag.py)). Cycle detection is enforced at **config load** (the loader builds the DAG via a lazy import) so a cycle fails loudly during validation, not just at run time.
- [`bench/catalog/`](../bench/catalog/) — ports `shared/model_catalog.py` + `shared/experiments.py` into a config-driven `Catalog` (alias normalization, vanilla/null groups, colors, pricing). **Adds the orthodox `player_type` composition** (benchmark.md §3.3): `Catalog.compose_player_type(model, strategist, condition, config_slot)` builds the identity from per-player metadata (`model-{id}` + `strategist-{id}`) via the `player_type_template` + alias maps, then applies the unified `player_type_labels` map (leading-`-` ⇒ suffix, else full override; `(condition, slot)` beats `condition`; suffixes skipped for VPAI/Vanilla). The legacy `(condition, seat)` map is demoted to `Catalog.fallback_player_type` (legacy games with no metadata).
- [`bench/data/`](../bench/data/) — ports `shared/data_loading.py` (`load_turn_data`/`load_panel_data` + filters). **`player_type` is preferred from the CSV** (composed at extract); the static `(condition, player_id)` seat merge is fallback-only and catalog-driven.
- [`bench/stats/`](../bench/stats/) — ports `shared/regression_utilities.py` (OLS/logistic, clustered/weighted fits, coeff/odds-ratio heatmaps) verbatim except routing the coefficient/forest helpers through `bench.plotting`. Used by `performance.score_ratio`, `ratings.matchups`, `adjust/strength`.
- [`bench/plotting/`](../bench/plotting/) — ports `shared/plot_styles.py` (now catalog-parameterized, [`styles.py`](../bench/plotting/styles.py)) + the coefficient/forest helpers `stats/` imports ([`coefficients.py`](../bench/plotting/coefficients.py): `pvalue_to_stars`, `clean_variable_name`, `log_odds_to_prob_change`, `deviation_coefficients`, `prepare_coefficient_data`, `plot_forest_plot`). **Scope note:** the rest of the old 168 KB `plot_utilities.py` is notebook-/behavior-specific; per the plan's "trim notebook-only helpers", those plots are ported **per-analysis** in the stages that need them (4+), not dumped wholesale here.
- [`bench/rscript.py`](../bench/rscript.py) — cross-platform `Rscript` locator (`find_rscript`): `PATH` + the `CIV_BENCH_RSCRIPT` override only (D5 — the old hardcoded `C:`/`D:\Program Files\R` scan is dropped). Imported by the R-backed ratings + the controlled-design strength baseline in later stages.
- [`configs/models.json`](../configs/models.json), [`configs/experiments.json`](../configs/experiments.json), [`configs/paths.json`](../configs/paths.json) — ported from `../vox-deorum-analysis/shared/config/` and schema-extended; now the primary control surface. **Added catalog fields backing benchmark.md §3.3:** `player_type_template`, `vanilla_model_aliases`, `null_strategist_aliases`, `strategist_variant_map`, `vanilla_label`/`null_label` (models.json), and the unified `player_type_labels` map (experiments.json; empty by default — the metadata drives identity). The legacy per-seat `condition_player_mapping` is kept only as the optional fallback.

## Config wiring

- `catalogs` defaults to sibling `configs/*.json` paths and is loaded **lazily**: the loader reads `models.json` only when an `estimators` stage is present (for `prediction_models` membership), and a catalog that an enabled stage needs but cannot resolve fails loudly with the resolved path.
- **R discovery is cross-platform** via `bench/rscript.py` (`PATH` + `CIV_BENCH_RSCRIPT`); `scripts/install.ps1` likewise discovers `Rscript` via `Get-Command` (PATH), not a hardcoded path.
- **Output root** (benchmark.md §2.1): all stage save-paths (`estimators.save_predictions`, `adjust.save`, `report.out_dir`) authored under `reports/…` are re-rooted to `<root><suffix>/…` by `OutputConfig.resolve()`. The dry-run printer shows the resolved root and each stage's resolved write path.

## Scope notes (validated at stage 0, deferred where noted)

- **Per-module analysis `params`** are validated by each module as it lands (stages 3–5). Stage 0 validates the common envelope + cross-cutting rules: `group_by` dimensions resolve to defined `groupings`, `bootstrap.n` is an integer ≥ 1, strength controlled-design enums (`block`/`baseline_source`/`post_cell_normalize`/`engine`), filter presets/turn-range, estimator `fit`↔sub-block consistency, registry membership, unique/non-reserved ids, and acyclicity.
- The analysis/adjust **registries** in `schema.py` are the static name lists (core + optional) that benchmark.md must stay in parity with; each name gets a real implementation in its stage.

## Done

`civ-bench run --config configs/benchmark.dev.json --dry-run` (equivalently `--skip all`) — run from a local config copied from `configs/benchmark.pretrained.template.json` (`configs/benchmark.dev.json` is the worked dev instance) — loads and validates the config and prints the resolved DAG + the resolved output root (`reports-dev/`), with no stage executed. The non-dry `run` prints the DAG and exits 3 (stage execution arrives in stage 1+). ✅

## Verification (all passing)

- A deliberately malformed config fails loudly with a precise message — exercised for: unknown key (any level), missing required field, dangling `needs` (on an **estimator**, adjust, or analysis), dangling `uses`, disabled-target reference (an estimator `needs` a disabled stage; an analysis `uses` a disabled estimator), cycle, unknown analysis/adjust module, unknown estimator model, `fit`↔sub-block mismatch, ratings without a `strength` table, undefined `group_by` grouping, `bootstrap.n = 0`, bad strength enum, `turn_range` min > max, duplicate ids, and reserved ids (`extract`/`report`). 19/19 caught as `ConfigError` (estimators carry no `uses`, so `needs` is their only edge — and it is now validated like every other stage's, not silently dropped at DAG build).
- `import bench` works after `pip install -e .`; every submodule imports; the dry-run import path (`bench.cli`) pulls **no** torch/statsmodels/matplotlib. `scripts/install.ps1` installs + verifies every Python dependency and the R packages.
- Functional smoke: `Catalog.compose_player_type` reproduces §3.3 (alias-normalize, variant map, VPAI→Vanilla/Null, suffix-vs-override labels, slot-beats-condition, baseline skips suffix); `stats.fit_regression` + `plotting.plot_forest_plot` run; `data.load_turn_data` keeps the orthodox `player_type` and falls back to the seat map.
- A `tests/` suite formalizes the above: `pip install -e ".[test]" && pytest` (38 tests — config load/validation incl. all malformed cases and estimator-`needs` validation, DAG topology + extract-drop + cycle, output-root resolution, and the orthodox/​fallback player_type composition).
