# Stage 0: scaffold & infrastructure

**Goal.** Stand up the installable package, the JSON config loader/validator, the DAG pipeline, and the shared infra (catalogs, data, stats, plotting) that every later stage imports. After this stage a config can be loaded, validated, and its DAG printed, without running any analysis. **Status: built & validated.**

## Files created / ported

- [`pyproject.toml`](../pyproject.toml): `pip install -e .`, exposes the `civ-bench` CLI entrypoint (`bench.cli:main`); declares the full dependency set (see AGENTS.md §Dependencies) as plain requirements (no extras).
- [`bench/__init__.py`](../bench/__init__.py) (version only, kept import-light), [`bench/cli.py`](../bench/cli.py): `civ-bench extract|run|report` + `--config`/`--only`/`--skip`/`--dry-run`.
- [`bench/config/`](../bench/config/): load + validate the run-spec (`configs/benchmark*.json`) per [../configs/benchmark.md](../configs/benchmark.md) §8 (unknown keys / missing required = hard error); typed config objects ([`models.py`](../bench/config/models.py)); **resolves the output root** (default `reports`, configurable `suffix` → `reports-cross`) and threads it through `OutputConfig.resolve()`. Schema constants live in [`schema.py`](../bench/config/schema.py); pure filter resolution/narrowing in [`filters.py`](../bench/config/filters.py); shared stage-reference + dependency resolution in [`dependencies.py`](../bench/config/dependencies.py); the validator in [`loader.py`](../bench/config/loader.py).
- [`bench/pipeline/`](../bench/pipeline/): render the stage DAG from the config layer's cached, validated dependency graph ([`dag.py`](../bench/pipeline/dag.py)). The graph is resolved once at **config load** (kind-ordering + `needs` + `uses`, Kahn topo-sort, deterministic), so cycles and dangling/disabled references fail loudly during validation, and the dry-run path reuses the same resolved graph instead of recomputing dependency semantics.
- [`bench/catalog/`](../bench/catalog/): ports `shared/model_catalog.py` + `shared/experiments.py` into a config-driven `Catalog` (alias normalization, vanilla/null groups, colors, pricing) with cached alias/variant lookup tables. **Adds the orthodox `player_type` composition** (benchmark.md §3.3): `Catalog.compose_player_type(model, strategist, condition, config_slot)` builds the identity from per-player metadata (`model-{id}` + `strategist-{id}`) via the `player_type_template` + alias maps, then applies the unified `player_type_labels` map (leading-`-` ⇒ suffix, else full override; `(condition, slot)` beats `condition`; suffixes skipped for VPAI/Vanilla). The legacy `(condition, seat)` map is demoted to `Catalog.fallback_player_type` (legacy games with no metadata).
- [`bench/data/`](../bench/data/): ports `shared/data_loading.py` (`load_turn_data`/`load_panel_data` + filters). **`player_type` is preferred from the CSV** (composed at extract); the static `(condition, player_id)` seat merge is fallback-only and catalog-driven. The loaders also accept config-shaped filters via `apply_filter_spec`, reusing the same preset/list/intersection semantics that the config loader validates.
- [`bench/stats/`](../bench/stats/): ports `shared/regression_utilities.py` (OLS/logistic, clustered/weighted fits, coeff/odds-ratio heatmaps) verbatim except routing the coefficient/forest helpers through `bench.plotting`. Used by `performance.score_ratio`, `ratings.matchups`, `adjust/strength`.
- [`bench/plotting/`](../bench/plotting/): ports `shared/plot_styles.py` (now catalog-parameterized, [`styles.py`](../bench/plotting/styles.py)) + the coefficient/forest helpers `stats/` imports ([`coefficients.py`](../bench/plotting/coefficients.py): `pvalue_to_stars`, `clean_variable_name`, `log_odds_to_prob_change`, `deviation_coefficients`, `prepare_coefficient_data`, `plot_forest_plot`). **Scope note:** the rest of the old 168 KB `plot_utilities.py` is notebook-/behavior-specific; per the plan's "trim notebook-only helpers", those plots are ported **per-analysis** in the stages that need them (4+), not dumped wholesale here.
- [`bench/rscript.py`](../bench/rscript.py): cross-platform `Rscript` locator (`find_rscript`): `PATH` + the `CIV_BENCH_RSCRIPT` override only (D5; the old hardcoded `C:`/`D:\Program Files\R` scan is dropped). Imported by the R-backed ratings in later stages.
- [`configs/models.json`](../configs/models.json), [`configs/experiments.json`](../configs/experiments.json), [`configs/paths.json`](../configs/paths.json): ported from `../vox-deorum-analysis/shared/config/` and schema-extended; now the primary control surface. **Added catalog fields backing benchmark.md §3.3:** `player_type_template`, `vanilla_model_aliases`, `null_strategist_aliases`, `strategist_variant_map`, `vanilla_label`/`null_label` (models.json), and the unified `player_type_labels` map (experiments.json; nearly empty, because the metadata drives identity, with only a small label override such as `{"*-per-5": "-Per-5"}` shipped). The legacy per-seat `condition_player_mapping` is kept only as the optional fallback. **Alias resolution prefers an exact, else the longest, alias match** so a short alias (`minimax`) cannot shadow a longer model spelling that contains it (`minimax-m2.7`).

## Config wiring

- `catalogs` defaults to sibling `configs/*.json` paths and is loaded **lazily**: the loader reads `models.json` only when an `estimators` stage is present (for `prediction_models` membership), and a catalog that an enabled stage needs but cannot resolve fails loudly with the resolved path.
- **R discovery is cross-platform** via `bench/rscript.py` (`PATH` + `CIV_BENCH_RSCRIPT`); `scripts/install.ps1` likewise discovers `Rscript` via `Get-Command` (PATH), not a hardcoded path.
- **Output root** (benchmark.md §2.1): all stage save-paths (`estimators.save_predictions`, `adjust.save`, `report.out_dir`) authored under `reports/…` are re-rooted to `<root><suffix>/…` by `OutputConfig.resolve()`. `DagNode.resolved_save_path()` centralizes this for the runner/dry-run printer, and the dry-run printer shows the resolved root and each stage's resolved write path.

## Scope notes (validated at stage 0, deferred where noted)

- **Per-module analysis `params`** are validated by each module as it lands (stages 3–5). Stage 0 validates the common envelope + cross-cutting rules: string-list fields (`needs`, `uses.estimators`, `uses.tables`, `group_by`, extract `outputs`, report `formats`), stage filters only narrow the global data filter, `group_by` dimensions resolve to defined `groupings`, `bootstrap.n` is an integer ≥ 1, strength controlled-design enums (`block`/`post_cell_normalize`), filter presets/turn-range, estimator `fit`↔sub-block consistency, registry membership, unique/non-reserved ids, and acyclicity.
- The analysis/adjust **registries** in `schema.py` are the static name lists (core + optional) that benchmark.md must stay in parity with; each name gets a real implementation in its stage.

## Done

`civ-bench run --config configs/benchmark.dev.json --dry-run` (equivalently `--skip all`), run from a local config copied from `configs/benchmark.pretrained.template.json` (`configs/benchmark.dev.json` is the worked dev instance), loads and validates the config and prints the resolved DAG + the resolved output root (`reports-dev/`), with no stage executed. ✅ (Stages 1–5 have since landed, so a non-dry `run` now *executes* the full implemented pipeline; the exit-3 "skipped unimplemented stage(s)" path is defensive only: no current stage kind hits it.)

## Verification (all passing)

- A deliberately malformed config fails loudly with a precise message, exercised for: unknown key (any level), missing required field, dangling `needs` (on an **estimator**, adjust, or analysis), malformed string-list fields, dangling `uses`, disabled-target reference (an estimator `needs` a disabled stage; an analysis `uses` a disabled estimator), stage filter widening, cycle, unknown analysis/adjust module, unknown estimator model, `fit`↔sub-block mismatch, ratings without a `strength` table, undefined `group_by` grouping, `bootstrap.n = 0`, bad strength enum, `turn_range` min > max, `turn_range`/`min_games` bad element types, duplicate ids, and reserved ids (`extract`/`report`). All caught as `ConfigError` (estimators carry no `uses`, so `needs` is their only edge, and it is now validated like every other stage's, not silently dropped at DAG build). A ratings analysis may reference a strength table by **any** strength-stage id (the id doubles as the table name), not the literal `"strength"`.
- `import bench` works after `pip install -e .`; every submodule imports; the dry-run import path (`bench.cli`) pulls **no** torch/statsmodels/matplotlib. `scripts/install.ps1` installs + verifies every Python dependency and the R packages.
- Functional smoke: `Catalog.compose_player_type` reproduces §3.3 (alias-normalize, variant map, VPAI→Vanilla/Null, suffix-vs-override labels, slot-beats-condition, baseline skips suffix); `stats.fit_regression` + `plotting.plot_forest_plot` run; `data.load_turn_data` keeps the orthodox `player_type`, falls back to the seat map, and applies config-shaped filters.
- A `tests/` suite formalizes the above (the broader suite now totals 173 tests across all stages): config load/validation incl. all malformed cases, estimator-`needs` validation, and strength-table-by-id resolution; DAG topology + extract-drop + cycle + cached graph reuse; output-root resolution; config-shaped data filters; and the orthodox/​fallback player_type composition incl. alias-shadowing. Run with `pip install -e ".[test]" && pytest` (use `--basetemp` inside a sandbox that blocks the default temp root).
