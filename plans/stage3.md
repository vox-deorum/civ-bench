# Stage 3: adjust (strength panel)

**Goal.** Turn an estimator's per-turn `predicted_win_probability` into the per-player-game **`adjusted_strength`** panel and register it as the named `strength` table that `ratings.*` (and some `performance.*`) consume. This is the bridge that makes ratings depend transitively on an estimator.

## Files to create / port

- `bench/adjust/registry.py`: name → adjust class (currently only `strength`).
- `bench/adjust/runner.py` + `bench/adjust/__init__.py`: execute one adjust stage from the DAG, resolve its estimator artifact, canonical tables, and output-root-adjusted `save` path, then return a small result object for the CLI.
- `bench/adjust/strength.py`: port `prepare_strength_data` from `../vox-deorum-analysis/performance/turn_predicted.ipynb` (also copied in `ratings/iterative_bt.py`; consolidate to one place here). Core pipeline (unchanged): late-game weighted average (`turn_progress_min`, `weight`) → relative-to-leader (`relative_to`) → winner enforcement (`enforce_winner`) → finite `logit_strength = logit(clip(relative_strength, eps, 1-eps))`. Keep `relative_strength == 1.0` for enforced winners as an audit column, but every logit-scale fit/adjustment uses the clipped value.
  - **`relative_to` modes:** `"game_leader"` is the legacy relative-to-leader behavior (`relative_strength = win_prob / game_max`). The schema **also accepts `"none"`/`null`** ⇒ an *absolute* `relative_strength = win_prob` (no per-game leader normalization), and **`null` is the coded default** (`DEFAULT_PARAMS["relative_to"] = None`). ⚠️ **Legacy per-row parity therefore holds only when `relative_to:"game_leader"` is set explicitly**: a config that omits `relative_to` runs in absolute mode and will not reproduce the legacy `turn_predicted` values. The shipped `benchmark.{pretrained,full}.template.json` set `"game_leader"`; `benchmark.dev.json` omits it (absolute, by design).
  - **Parity details (so `block:"none"` matches legacy values):** (a) the estimator's `predictions.csv` carries an **unrounded** `turn_progress` (stage 2), but the legacy pipeline groups/weights on `round(turn/max_turn, 2)` (legacy `load_turn_data` overwrites the column). **Re-round `turn_progress` to 2 decimals** inside strength before the per-`turn_progress` average and the `weight`, or the averaging collapses and the weights drift. The `turn_progress_min` filter is strict `>` (legacy uses `> 0.2`). (b) Pin `eps = 1e-5` to match the legacy `logit` clip; port `logit`/`inv_logit` into `bench/stats/` (they have no home in `bench` yet) and import them from there. (c) `player_type`/`config_slot` are **not** in `predictions.csv`: join them from `panel_data` by `(game_id, player_id)`; join `seed`/`seating_rotation` from the `games` table by `game_id`; take `civilization` from `predictions.csv` (panel as fallback). (d) The panel **keeps all rows**: the legacy Step 6 `filter_non_llm_games` is **dropped**; vanilla/null seats stay in the panel so `ratings.* ref="Vanilla"` and the baseline pathways still resolve, and analyses do their own `only_llm` filtering. Consequently `block:"none"` reproduces the legacy **per-row values** (`relative_strength`, `logit_strength`, `adjusted_strength`) for shared rows, but the panel additionally retains the non-LLM-experiment rows legacy filtered out.
- `bench/cli.py`: add `adjust` to the implemented stage kinds and dispatch `node.kind == "adjust"` to the new adjust runner, so `civ-bench run` actually produces the named table instead of reporting stage 3 as skipped.

## The adjustment step: civ (uncontrolled) vs matched start-cell (controlled)

After `logit_strength`, the panel is split by `controlled = (seed != -1 and seating_rotation != -1)`. Join game-level `seed`/`seating_rotation` from the `games` table by `game_id`; keep per-player `config_slot` from `panel_data` by `(game_id, player_id)`:

- **Uncontrolled rows** keep today's behavior: OLS-logit **civ** adjustment (`civ_adjust`, uses `bench/stats/`). `civ_adjust:"none"` ⇒ `adjusted_strength == relative_strength`. The per-civ effects it subtracts are always written to `<adjust dir>/civ_effects.csv` (below). Preserve the legacy formula `logit_strength ~ C(civilization, Sum) + C(player_type, Treatment(reference=<vanilla_label>))`: keep the `player_type` covariate, and take the reference level from `catalog.vanilla_label` (not a hardcoded `"Vanilla"`). The **OLS is fit on all panel rows** (matching legacy, which fit before any LLM filter); controlled rows are included in the fit even though they take the cell path, and only uncontrolled rows have the civ effect subtracted from their `adjusted_strength`. Do not inherit the old hardcoded `Venice` omitted-level assumption: discover the omitted Sum-coded civilization from the fitted data (`all civilizations - parsed civ terms`) and set that effect to `-sum(observed effects)`.
- **Controlled rows** take the **matched final-seat cell** path (benchmark.md §5.1), selected by `block` (`none|start_cell|auto`; `auto` ⇒ `start_cell` when controlled rows exist). The adjustment cell is always the final in-game seating/start-position cell `start_cell = (seed, player_id)`: `seed` identifies the generated map/start layout, and `player_id` identifies the final seat/start position after rotation. `config_slot` is retained for diagnostics about which configured model rotated into a cell, but it is not the baseline cell. Subtract a per-cell **Vanilla VPAI baseline** via one or both pathways. Here "Vanilla VPAI baseline" is deliberately narrow: baseline evidence is rows whose raw model is VPAI when that column is available and whose composed `player_type` equals `catalog.vanilla_label` (`Vanilla` by default). `Null` is not baseline evidence unless a later explicit param says otherwise.
  - **Explicit baseline** (`baseline_experiment` set, e.g. a pure VP self-play condition where every seat is VPAI): for each `(seed, player_id)` cell, average the designated experiment's Vanilla/VPAI `logit_strength` rows. In seated mode, the `n` rotations for a seed are repeated observations of the same generated map/start cells, so `player_id=1, seed=1` has up to `n` repeated Vanilla observations; the explicit baseline is their logit-scale mean, with no cross-cell smoothing/model fit.
  - **Implicit baseline** (`baseline_experiment` unset, default): for each controlled experiment and `(seed, player_id)` cell, average that experiment's own Vanilla/VPAI `logit_strength` rows. **Incomplete self-coverage is expected (rotation sparsity) and is NOT fatal under implicit:** every cell with `n_vanilla >= 1` is adjusted via its logit-scale cell mean, and any cell with `n_vanilla == 0` falls back to the uncontrolled adjustment (`civ_adjust` when `ols_logit`, else `relative_strength`) with a WARN naming the offending `(experiment, seed, player_id)` cells. No cross-cell or cross-condition pooling is used for the primary point adjustment. (Explicit selection stays fatal on a missing cell; see Coverage below.)
  - Subtract: `adjusted_strength = inv_logit(logit_strength − cell_baseline)`. The final-seat cell fixes the seat-bound civ, so this **replaces** civ adjustment for controlled rows *that have a cell baseline*; implicit cells without one fall back to civ adjustment (above). A per-row `adjust_method` audit column (`cell|civ|relative`) records which path each row took. Optional final `post_cell_normalize` (`none|relative_to_leader`).
  - **Selected pathway + comparison pathway.** If `baseline_experiment` is set, explicit feeds `adjusted_strength`; implicit is still computed per controlled experiment wherever that experiment has Vanilla/VPAI rows, so the report can show explicit-vs-implicit deltas. If `baseline_experiment` is unset, implicit feeds `adjusted_strength`; no explicit rows are reported. Coverage gaps in the comparison pathway are shown, never fatal.
- **Coverage: throw vs. warn.** *Hard error (selected **explicit** only):* a controlled row whose selected **explicit** baseline cell is missing aborts the stage, naming the offending `(experiment, seed, player_id)` cells; the designated `baseline_experiment` is meant to span the whole start grid, so a hole there is a config/data error. *WARN, never abort (selected **implicit**):* a controlled row whose own-experiment cell has no VPAI counterpart is not fatal: that cell falls back to the uncontrolled adjustment and the run proceeds (incomplete self-coverage from sparse rotations is expected). Also WARN-only: per-model cell coverage (using `config_slot` from `panel_data` and `seating_rotation` from `game_data`), connectedness-to-`Vanilla` (union-find; extrapolated models warned), and any coverage gap in a comparison pathway computed only for the report. Outside a missing **explicit** cell, keep all games and proceed.
- **Cell-coverage report (controlled only): which cells each experiment is missing.** Against the **entirety** of the reference cell grid, report per controlled experiment which `(seed, player_id)` cells it does not cover. The "entirety" is the full baseline cell set: when `baseline_experiment` is set, it is the `(seed, player_id)` cells the baseline experiment covers (a pure VP self-play seats VPAI in every position across every seed/rotation, so it spans the whole start grid); when unset (implicit), it is the union of `(seed, player_id)` cells observed across the controlled subset. This is a completeness diagnostic over the controlled design (**report-only, WARN, never fatal**; independent of the hard-error "row needs adjustment but its baseline cell is missing" above), written to `cell_coverage.csv` (below) and surfaced by `performance.strength_panel`. It is empty (headers only) when there are no controlled rows.
- **Estimator/filter precondition.** The strength stage does not re-infer predictions; it consumes the referenced estimator's saved `predictions.csv`. Therefore controlled `block != "none"` requires that artifact to include the Vanilla baseline rows needed by the selected pathway. A global `data.filter`/estimator `predict_subset` such as `only_llm` can remove those rows; selected implicit then fails with the missing-cell error, and selected explicit fails if the designated `baseline_experiment` rows are absent. Templates should keep estimator prediction broad (`predict_subset:"all"`; global filters that retain Vanilla references) and let analyses narrow later.
- **Always-written adjustment trails (no config, like every other audit artifact).** The stage writes the intermediate per-group values it subtracts, next to the panel (the directory of `save`, default `reports/adjust/`): `civ_effects.csv` (per-`civilization`: `civilization, civ_effect, n_rows`, the civilization-level effect from the uncontrolled path) and `cell_baseline.csv` (the VPAI seating×seed effect from the controlled path: `experiment, pathway, seed, player_id, civilization, cell_baseline, n_vanilla, n_games, n_models, has_vanilla_baseline, vanilla_connected`). `cell_baseline.csv` carries every pathway that actually ran (`pathway ∈ {explicit, implicit}`), so a `baseline_experiment:null` run normally has only implicit rows. When both explicit and implicit exist for a condition/cell, the report compares `implicit - explicit` on the logit scale. `civ_effects.csv` is generated whenever the civ-adjustment OLS ran (`civ_adjust:"ols_logit"`); since that OLS is fit on **all** panel rows (§3: controlled rows included in the fit, just not subtracted), it is written even on a fully controlled run, and `n_rows` counts controlled+uncontrolled rows per civ. Additionally `cell_coverage.csv` (the controlled-design completeness report above) is written whenever controlled rows exist: one row per `(experiment, seed, player_id)` over the **entirety** grid × controlled experiments (`experiment, seed, player_id, civilization, in_entirety, n_rows, n_vanilla, has_baseline, missing`), with `missing = true` for cells of the entirety the experiment has no rows for (`civilization` is the seat-bound civ from the entirety). Empty CSVs with headers are acceptable when a path is skipped because no rows of that kind exist (e.g. `cell_baseline.csv`/`cell_coverage.csv` on a fully uncontrolled run). `performance.strength_panel` surfaces them in the report.

`bench/stats/` remains the OLS/logistic helper layer for civ adjustment; no mixed-model/shrinkage machinery is needed for stage 3.

## Config wiring (`adjust[]`)

The stage `id` doubles as the table name. `uses.estimators` is required and single-source (point at `attention` per `benchmark.pretrained.template.json` / `benchmark.dev.json`). Saves to `<root>/adjust/player_strength_panel.csv`. New params: `block`, `post_cell_normalize`, and **`baseline_experiment`** (string experiment id, default `null` ⇒ implicit per-experiment path; a value ⇒ explicit-baseline path). `baseline_experiment` is **type-checked only** at config load (string-or-null), **not** validated against the experiment catalog: a wrong id fails late at run time (fatal "missing explicit baseline cell" on a controlled run; ignored on a fully uncontrolled run), because valid experiment ids can come from extracted data the catalog need not enumerate. With `block:"none"` (or no controlled rows) the stage is byte-identical to the civ-only pipeline, except for any newly documented audit columns/files that are ignored by legacy consumers.

Strength `params` gets a real schema in `bench/config/loader.py`, not just enum checks: reject unknown keys; validate `turn_progress_min` as numeric in `[0, 1]`; `weight ∈ {turn_progress, uniform}`; `relative_to ∈ {game_leader, none}` (nullable; `null`/`"none"` ⇒ absolute); `enforce_winner` as bool; `civ_adjust ∈ {none, ols_logit}`; `block ∈ {none, start_cell, auto}`; `post_cell_normalize ∈ {none, relative_to_leader}`; `baseline_experiment` as **string-or-null, type-checked only**: its value is **not** validated against the experiment catalog at config load (experiment ids can be inferred from extracted data the catalog need not list). A wrong id therefore fails *late*: a controlled run aborts with the "missing explicit baseline cell" `AdjustError`, while a fully uncontrolled run ignores it (no cell path runs).

## Done

`<root>/adjust/player_strength_panel.csv` exists with at least `game_id, player_id, player_type, civilization, relative_strength, logit_strength, adjusted_strength` (plus `experiment`, `controlled` = `seed != -1 and seating_rotation != -1`, and `seed`/`seating_rotation`/`config_slot` pass-through so the report can judge preliminary-ness), and is registered so a downstream `uses.tables:["strength"]` resolves and adds the edge. The intermediate trails `<root>/adjust/civ_effects.csv`, `<root>/adjust/cell_baseline.csv`, and `<root>/adjust/cell_coverage.csv` are written automatically (the latter two only when controlled rows exist; `cell_baseline.csv` pathways only when their source exists). `civ-bench run` executes adjust stages in DAG order and reports the output path/row count, not "stage 3 skipped".

## Verification

- Column contract present (incl. `experiment`, `controlled`, and the `adjust_method` audit pass-through); winner rows have `relative_strength == 1.0` when `enforce_winner:true`, while `logit_strength` remains finite via clipping.
- `block:"none"` reproduces the old `turn_predicted` **per-row values** (`relative_strength`, `logit_strength`, `adjusted_strength`) on the same estimator, for the rows the two pipelines share. The new panel additionally retains the non-LLM-experiment rows that legacy's Step 6 `filter_non_llm_games` dropped (that filter is intentionally not ported; analyses apply `only_llm`). Parity requires the 2dp `turn_progress` re-rounding and `eps=1e-5` noted above.
- On controlled synthetic data with a known per-cell Vanilla baseline + a known uplift: the estimated baseline recovers the baseline, `adjusted_strength` recovers the uplift, and `ratings.vanilla_slot_effect` goes from significant (raw) to ~null (adjusted).
- **Explicit pathway:** a designated `baseline_experiment` (pure VP self-play) averages all VPAI rows per `(seed, player_id)` final-seat cell on the logit scale, uses that baseline downstream, and recovers the injected uplift.
- **Implicit pathway:** computes every complete cell and **does not throw** on incomplete self-coverage: a final-seat cell with no VPAI counterpart falls back to the uncontrolled adjustment (`adjust_method` ⇒ `civ`/`relative`) and is named in a WARN, while complete cells still recover the baseline/uplift.
- `cell_baseline.csv` contains the selected pathway and contains the comparison pathway only when its source exists; a `baseline_experiment:null` run is allowed to contain only `implicit`. When both pathways exist for a condition/cell, the report can compute explicit-vs-implicit deltas.
- Non-selected-pathway / per-model / disconnected coverage gaps warn (never abort); a missing **selected explicit** baseline cell is fatal, while a missing **selected implicit** cell warns and falls back.
- `cell_coverage.csv` (controlled only) enumerates, against the entirety reference grid, every `(seed, player_id)` cell each controlled experiment is missing (`missing=true`); on a synthetic controlled design with a deliberately dropped cell, that cell shows up as `missing` for the experiment lacking it and as present for the baseline. The file is report-only (never fatal) and is empty (headers only) on a fully uncontrolled run.
- The `civ_effects.csv` / `cell_baseline.csv` trails reconcile with the panel: subtracting the trail value (civ effect or cell baseline) from the persisted clipped `logit_strength` reproduces `adjusted_strength`.
- CLI integration: `civ-bench run --only strength` runs extract/estimator deps plus the adjust stage and writes the panel; dry-run shows the output-root-resolved save path.
- Config validation rejects unknown strength params and bad domains/types. `baseline_experiment` is type-checked (string-or-null) but **not** resolved against the experiment catalog at config load (a wrong id fails late, per Config wiring).
