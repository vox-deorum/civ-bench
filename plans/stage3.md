# Stage 3 — adjust (strength panel)

**Goal.** Turn an estimator's per-turn `predicted_win_probability` into the per-player-game **`adjusted_strength`** panel and register it as the named `strength` table that `ratings.*` (and some `performance.*`) consume. This is the bridge that makes ratings depend transitively on an estimator.

## Files to create / port

- `bench/adjust/registry.py` — name → adjust class (currently only `strength`).
- `bench/adjust/runner.py` + `bench/adjust/__init__.py` — execute one adjust stage from the DAG, resolve its estimator artifact, canonical tables, and output-root-adjusted `save` path, then return a small result object for the CLI.
- `bench/adjust/strength.py` — port `prepare_strength_data` from `../vox-deorum-analysis/performance/turn_predicted.ipynb` (also copied in `ratings/iterative_bt.py` — consolidate to one place here). Core pipeline (unchanged): late-game weighted average (`turn_progress_min`, `weight`) → relative-to-leader (`relative_to`) → winner enforcement (`enforce_winner`) → finite `logit_strength = logit(clip(relative_strength, eps, 1-eps))`. Keep `relative_strength == 1.0` for enforced winners as an audit column, but every logit-scale fit/adjustment uses the clipped value.
- `bench/cli.py` — add `adjust` to the implemented stage kinds and dispatch `node.kind == "adjust"` to the new adjust runner, so `civ-bench run` actually produces the named table instead of reporting stage 3 as skipped.

## The adjustment step — civ (uncontrolled) vs matched start-cell (controlled)

After `logit_strength`, the panel is split by `controlled = (seed != -1 and seating_rotation != -1)`. Join game-level `seed`/`seating_rotation` from the `games` table by `game_id`; keep per-player `config_slot` from `panel_data` by `(game_id, player_id)`:

- **Uncontrolled rows** keep today's behavior: OLS-logit **civ** adjustment (`civ_adjust`, uses `bench/stats/`). `civ_adjust:"none"` ⇒ `adjusted_strength == relative_strength`. The per-civ effects it subtracts are always written to `<adjust dir>/civ_effects.csv` (below). Do not inherit the old hardcoded `Venice` omitted-level assumption: discover the omitted Sum-coded civilization from the fitted data (`all civilizations - parsed civ terms`) and set that effect to `-sum(observed effects)`.
- **Controlled rows** take the **matched final-seat cell** path (benchmark.md §5.1), selected by `block` (`none|start_cell|auto`; `auto` ⇒ `start_cell` when controlled rows exist). The adjustment cell is always the final in-game seating/start-position cell `start_cell = (seed, player_id)`: `seed` identifies the generated map/start layout, and `player_id` identifies the final seat/start position after rotation. `config_slot` is retained for diagnostics about which configured model rotated into a cell, but it is not the baseline cell. Subtract a per-cell **Vanilla VPAI baseline** via one or both pathways. Here "Vanilla VPAI baseline" is deliberately narrow: baseline evidence is rows whose raw model is VPAI when that column is available and whose composed `player_type` equals `catalog.vanilla_label` (`Vanilla` by default). `Null` is not baseline evidence unless a later explicit param says otherwise.
  - **Explicit baseline** (`baseline_experiment` set, e.g. a pure VP self-play condition where every seat is VPAI): for each `(seed, player_id)` cell, average the designated experiment's Vanilla/VPAI `logit_strength` rows. In seated mode, the `n` rotations for a seed are repeated observations of the same generated map/start cells, so `player_id=1, seed=1` has up to `n` repeated Vanilla observations; the explicit baseline is their logit-scale mean, with no cross-cell smoothing/model fit.
  - **Implicit baseline** (`baseline_experiment` unset, default): for each controlled experiment and `(seed, player_id)` cell, average that experiment's own Vanilla/VPAI `logit_strength` rows. If a controlled downstream cell has `n_vanilla == 0`, throw when implicit is the selected pathway; if `n_vanilla >= 1`, use the logit-scale mean. No cross-cell or cross-condition pooling is used for the primary point adjustment.
  - Subtract: `adjusted_strength = inv_logit(logit_strength − cell_baseline)`. The final-seat cell fixes the seat-bound civ, so this **replaces** civ adjustment for controlled rows. Optional final `post_cell_normalize` (`none|relative_to_leader`).
  - **Selected pathway + comparison pathway.** If `baseline_experiment` is set, explicit feeds `adjusted_strength`; implicit is still computed per controlled experiment wherever that experiment has Vanilla/VPAI rows, so the report can show explicit-vs-implicit deltas. If `baseline_experiment` is unset, implicit feeds `adjusted_strength`; no explicit rows are reported. Coverage gaps in the comparison pathway are shown, never fatal.
- **Coverage — throw vs. warn.** *Hard error (selected pathway only):* any controlled row needing adjustment whose selected baseline is missing aborts the stage, naming the offending `(experiment, seed, player_id)` cells. For selected explicit, this means the designated baseline experiment has no VPAI row for that `(seed, player_id)` cell. For selected implicit, this means that experiment has no VPAI row for that `(seed, player_id)` cell. *WARN, never abort:* per-model cell coverage (using `config_slot` from `panel_data` and `seating_rotation` from `game_data`), connectedness-to-`Vanilla` (union-find; extrapolated models warned), and any coverage gap in a comparison pathway computed only for the report. Outside selected-baseline missing cells, keep all games and proceed.
- **Estimator/filter precondition.** The strength stage does not re-infer predictions; it consumes the referenced estimator's saved `predictions.csv`. Therefore controlled `block != "none"` requires that artifact to include the Vanilla baseline rows needed by the selected pathway. A global `data.filter`/estimator `predict_subset` such as `only_llm` can remove those rows; selected implicit then fails with the missing-cell error, and selected explicit fails if the designated `baseline_experiment` rows are absent. Templates should keep estimator prediction broad (`predict_subset:"all"`; global filters that retain Vanilla references) and let analyses narrow later.
- **Always-written adjustment trails (no config — like every other audit artifact).** The stage writes the intermediate per-group values it subtracts, next to the panel (the directory of `save`, default `reports/adjust/`): `civ_effects.csv` (per-`civilization`: `civilization, civ_effect, n_rows`, the civilization-level effect from the uncontrolled path) and `cell_baseline.csv` (the VPAI seating×seed effect from the controlled path: `experiment, pathway, seed, player_id, civilization, cell_baseline, n_vanilla, n_games, n_models, has_vanilla_baseline, vanilla_connected`). `cell_baseline.csv` carries every pathway that actually ran (`pathway ∈ {explicit, implicit}`), so a `baseline_experiment:null` run normally has only implicit rows. When both explicit and implicit exist for a condition/cell, the report compares `implicit - explicit` on the logit scale. `civ_effects.csv` is generated whenever the uncontrolled path ran. Empty CSVs with headers are acceptable when a path is skipped because no rows of that kind exist. `performance.strength_panel` surfaces them in the report.

`bench/stats/` remains the OLS/logistic helper layer for civ adjustment; no mixed-model/shrinkage machinery is needed for stage 3.

## Config wiring (`adjust[]`)

The stage `id` doubles as the table name. `uses.estimators` is required and single-source (point at `attention` per `benchmark.pretrained.template.json` / `benchmark.dev.json`). Saves to `<root>/adjust/player_strength_panel.csv`. New params: `block`, `post_cell_normalize`, and **`baseline_experiment`** (string experiment id, default `null` ⇒ implicit per-experiment path; a value ⇒ explicit-baseline path). `baseline_experiment`, when set, must name a known experiment id (validated at config-load → `ConfigError`). With `block:"none"` (or no controlled rows) the stage is byte-identical to the civ-only pipeline, except for any newly documented audit columns/files that are ignored by legacy consumers.

Strength `params` gets a real schema in `bench/config/loader.py`, not just enum checks: reject unknown keys; validate `turn_progress_min` as numeric in `[0, 1]`; `weight ∈ {turn_progress, uniform}`; `relative_to ∈ {game_leader}` for now; `enforce_winner` as bool; `civ_adjust ∈ {none, ols_logit}`; `block ∈ {none, start_cell, auto}`; `post_cell_normalize ∈ {none, relative_to_leader}`; `baseline_experiment` as string-or-null and known experiment id when present.

## Done

`<root>/adjust/player_strength_panel.csv` exists with at least `game_id, player_id, player_type, civilization, relative_strength, logit_strength, adjusted_strength` (plus `experiment`, `controlled` = `seed != -1 and seating_rotation != -1`, and `seed`/`seating_rotation`/`config_slot` pass-through so the report can judge preliminary-ness), and is registered so a downstream `uses.tables:["strength"]` resolves and adds the edge. The intermediate trails `<root>/adjust/civ_effects.csv` and `<root>/adjust/cell_baseline.csv` are written automatically (pathways for the latter only when their source exists). `civ-bench run` executes adjust stages in DAG order and reports the output path/row count, not "stage 3 skipped".

## Verification

- Column contract present (incl. `experiment`, `controlled` pass-through); winner rows have `relative_strength == 1.0` when `enforce_winner:true`, while `logit_strength` remains finite via clipping.
- `block:"none"` reproduces the old `turn_predicted` output byte-for-byte on the same estimator.
- On controlled synthetic data with a known per-cell Vanilla baseline + a known uplift: the estimated baseline recovers the baseline, `adjusted_strength` recovers the uplift, and `ratings.vanilla_slot_effect` goes from significant (raw) to ~null (adjusted).
- **Explicit pathway:** a designated `baseline_experiment` (pure VP self-play) averages all VPAI rows per `(seed, player_id)` final-seat cell on the logit scale, uses that baseline downstream, and recovers the injected uplift.
- **Implicit pathway:** **throws** when a controlled experiment has a final-seat cell with no VPAI counterpart; succeeds and recovers the baseline when every adjusted cell has one or more VPAI rows.
- `cell_baseline.csv` contains the selected pathway and contains the comparison pathway only when its source exists; a `baseline_experiment:null` run is allowed to contain only `implicit`. When both pathways exist for a condition/cell, the report can compute explicit-vs-implicit deltas.
- Non-selected-pathway / per-model / disconnected coverage gaps warn (never abort); selected explicit/implicit missing-source errors are fatal.
- The `civ_effects.csv` / `cell_baseline.csv` trails reconcile with the panel: subtracting the trail value (civ effect or cell baseline) from the persisted clipped `logit_strength` reproduces `adjusted_strength`.
- CLI integration: `civ-bench run --only strength` runs extract/estimator deps plus the adjust stage and writes the panel; dry-run shows the output-root-resolved save path.
- Config validation rejects unknown strength params and bad domains/types, including an invalid `baseline_experiment` id.
