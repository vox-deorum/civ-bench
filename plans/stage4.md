# Stage 4 — analyses

**Goal.** Implement the pluggable analysis layer and the **core** modules. Each is a self-contained unit behind the `Analysis` interface + registry; JSON selects it by name; it returns an `AnalysisResult` (tables + figures + summary), never side effects.

## Files to create / port

- `bench/analyses/base.py` — `Analysis` interface + registry (name → class) and `AnalysisResult`.
- **ratings** (`analyses/ratings/`, consume `strength` via `uses.tables:["strength"]`): `ratings.bradley_terry`, `ratings.plackett_luce`, `ratings.matchups`. Port from `../vox-deorum-analysis/ratings/` (keep R interop; `Rscript` via `PATH`/`CIV_BENCH_RSCRIPT`). **strategy-Elo and bootstrap are params, not modules:** `group_by` (default `["player_type"]`; `["player_type","strategy"]` = per-strategy) and `bootstrap` (shared resample-and-refit). **The `bootstrap` resample re-runs only the parts of the `adjust/strength` fit that are themselves re-estimated from the resampled games** (resample games upstream of the strength fit, not a fixed panel), so a quantity propagates uncertainty into the CIs exactly when it is recomputed from the bootstrap sample: under the **implicit** pathway the per-cell baseline is estimated from each experiment's own (resampled) Vanilla/VPAI rows, so it **must** be refit inside every replicate; under an **explicit** `baseline_experiment` the cell baseline is a fixed designated reference panel (a separate high-`n` VP self-play grid treated as a known reference), so it is held **constant** across replicates and only the focal rows resample — no per-replicate baseline refit. Likewise the uncontrolled path: `civ_adjust:"none"` needs no refit, while `civ_adjust:"ols_logit"` re-fits the civ OLS per replicate.
- **prediction** (scoring, `analyses/prediction/`): `prediction.evaluate` (multi-metric table), `prediction.compare`. Port from `predict/` loader + comparison logic.
- **calibration** (`analyses/calibration/`): `calibration.reliability`, `calibration.loss_by_progress`, `calibration.civ_effects`, `calibration.cell_baseline`.
  - **`calibration.cell_baseline` (controlled-design only) — implicit-vs-explicit cell-baseline heatmap.** Consumes the adjust stage's `cell_baseline.csv` (+ `cell_coverage.csv` for missing-cell marking); renders **per `seed`** (split so each panel stays small) a heatmap whose **rows are conditions** (`experiment` — the implicit per-experiment baselines) and whose **columns are the `(seed, player_id)` cells** of that seed, each column labeled with its seat-bound `civilization` (fixed per `(seed, player_id)`). Cell color = `cell_baseline` on the **logit scale**: a diverging map centered at 0 with **shared, robust symmetric limits** across the per-seed facets — percentile-clipped so the enforced-winner/clip sentinel `logit(1−eps) ≈ 11.51` does not saturate the scale, with sentinel/clipped cells given a distinct marker. Each cell is annotated with **`n_vanilla`** — the count of Vanilla/VPAI rows the baseline averages (the estimate's support); cells the experiment is missing (`cell_coverage.missing` / `n_vanilla == 0`) are hatched/blanked. Because the **explicit pathway is the single shared baseline** spanning the whole grid, it is pinned as a **top reference row separated by a rule**, so each implicit condition's cell can be read against the explicit baseline directly above it; both pathways are drawn together when present, and an implicit-only (`baseline_experiment:null`) run omits the explicit reference row. Emits one figure per `seed` in `AnalysisResult.figures`; returns an empty result (no figures) when there are no controlled rows. Adds a catalog-styled `bench/plotting/heatmap.py` (ported per the stage-0 "plotting helpers per-analysis as needed" convention).
  - **`calibration.civ_effects` (uncontrolled path) — per-civilization adjustment effects.** Visualizes the adjust stage's `civ_effects.csv` (`civilization, civ_effect, n_rows`): a **sorted horizontal bar/lollipop** of `civ_effect` on the **logit scale**, diverging-colored by sign and centered at 0 (the Sum-coded effects sum to ~0), each bar annotated with **`n_rows`** — the panel rows backing that civ's effect. This is the uncontrolled counterpart to `calibration.cell_baseline`'s controlled per-cell baseline; `civ_effects.csv` carries no CI (it is a single point OLS effect), so it is a bar/lollipop, **not** a forest plot (the existing `plot_forest_plot` needs CIs). Renders only when `civ_effects.csv` is non-empty (the uncontrolled `civ_adjust:"ols_logit"` path ran); empty result (no figures) otherwise.
- **performance** (`analyses/performance/`): `performance.score_ratio` (uses `stats/`), `performance.strength_panel` (consumes `strength`), `performance.turn_predicted` (uses an estimator). **`performance.strength_panel` always reports per-identity `n_games` + bootstrap CI *and* flags identities below `min_games_preliminary` (default = ratings `min_games`) as preliminary; the adjust stage's three audit trails are surfaced in exactly one place each — no overlap: the per-civ uncontrolled effect (`civ_effects.csv`) by `calibration.civ_effects` and the per-cell controlled baseline (`cell_baseline.csv`, both pathways, stage3 §5.1) by `calibration.cell_baseline` (both calibration group above), while `strength_panel` owns the controlled-design **cell-coverage report** (`cell_coverage.csv` — which `(seed, player_id)` cells of the entirety each controlled experiment is missing), rendered once here as its preliminary-ness completeness table; `calibration.cell_baseline` only *consumes* that file to mark missing cells, it does not re-render the coverage table.**
- **exploratory** (`analyses/exploratory/`): `exploratory.model_token_costs` (tokens table + pricing).
- Optional modules (ablation_bt, vanilla_slot_effect, winner_trajectories, elo_comparison, context_slicing, permutation_importance, panel, turn, strategy_profiles) are **registry-reserved, `enabled:false`**, shipped only in `benchmark.full.template.json`. `behavior.*` is deferred (not built). **`ratings.vanilla_slot_effect` doubles as the controlled-design validation**: with stage3's start-cell adjustment on, the seat/start-position effect should be significant on the raw panel and ~null on the adjusted panel.

## Config wiring (`analyses[]`)

Common envelope: `id`, `module`, `uses.{estimators,tables}`, `filter` (narrows the global filter), `params`. `ratings.*` must reference a `strength` table; metrics live in `prediction.evaluate`, not in the estimator.

## Done

Every core analysis runs and returns a populated `AnalysisResult`; unknown `params` are validation errors; `group_by:["player_type","strategy"]` produces per-strategy ratings via the `strategy` grouping.

## Verification

- Each core module's tables match the old notebook/script output on the same inputs (within tolerance).
- R-backed ratings run on a machine where `Rscript` is only on `PATH` (no hardcoded path).
